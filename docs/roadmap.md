# 个人量化交易控制台：总计划与执行基线

## 目标

构建一个面向个人研究者的 paper-only 量化平台，覆盖数据管理、特征、因子、市场状态、策略、回测、仿真、风险、AI 研究和实盘辅助。平台不承诺盈利，真实交易默认关闭，任何实盘能力必须经过人工确认和独立风控闸门。

## 已完成基线

- Python 模块化项目和配置系统。
- CSV 行情导入、数据质量校验和基础回测。
- QMT/CTP/MT5 paper 适配器注册。
- DeepSeek OpenAI-compatible 研究调用，AI 无执行权限。
- Tushare Pro ETF 日线适配和研究工具调用。
- ECB EURUSD 日线 CSV 研究数据。
- 数据集版本指纹与质量报告。
- 基础特征：收益率、动量、波动率、ATR、均线偏离、成交量比率。
- 因子：去极值、Z-Score、分组收益、IC、Rank IC、按日 IC 序列、ICIR、衰减、自相关、换手率、容量估计和样本内/样本外拆分。
- 本地 HTTP 控制台和访达双击后台启动脚本。

## 阶段计划

### 1. 数据中心

统一 `MarketEvent`、K 线、逐笔成交、盘口、订单流、基本面和宏观数据契约；增加数据源适配器、质量报告、版本目录、缓存和更新时间。Tushare 用于 A 股/ETF 研究，CTP/MT5 用于对应市场，ATAS X 通过 C# 桥接只读订单流。

### 2. 特征与因子

建立特征注册表、公式版本、参数快照和防未来数据检查；增加分组收益、IC 时间序列、ICIR、衰减、自相关、相关性、容量和市场状态条件分析。

### 3. 市场状态

先实现可解释规则：均线结构、ATR、滚动波动率分位数、ADX；再预留 HMM。所有状态判断记录依据、时间和版本。

### 4. 策略

先实现单资产 CTA、趋势、动量、突破、均值回归和波动率定仓。每个策略保存入场、出场、成本、滑点、风险限制和适用状态。

### 5. 回测

快速回测用于筛选；事件驱动回测按时间处理信号、延迟、撮合、部分成交、手续费、滑点、资金、交易时段、涨跌停和合约换月。强制样本内/样本外划分并防止未来数据。

### 6. 仿真与订单特征

实现虚拟账户、订单状态、成交模拟、异常断线和风控拦截；增加 ATAS/MT5/CTP 订单和订单流标准化字段，计算买卖不平衡、大单、盘口深度、VWAP 偏离和成交冲击。

### 7. 风控与实盘辅助

实现仓位、风险预算、波动率目标、单日亏损、最大回撤、连续亏损、流动性、API 异常、断网和全局熔断。实盘接口只允许模拟账户起步，并保留人工确认。

### 8. AI Agent 与控制台

AI 只调用白名单只读工具；回答必须附数据源、工具执行状态、数据条数和错误信息。控制台逐步增加 Dashboard、数据中心、特征、因子、市场状态、策略、回测、仿真、风险和日志页面。

### 9. 机器学习与多 Agent 组合研究流水线

以 A 股 ETF 作为首个试点，个股和国内期货仅在 ETF 样本外与仿真验收通过后扩展。该流水线是研究增强模块，不承诺盈利，也不直接获得交易执行权限。

#### 9.1 初筛与稳健预测层：Qlib + LightGBM + DoubleEnsemble

- 使用 Qlib 统一数据集、特征标签、训练区间、验证区间和滚动样本外区间。
- LightGBM 作为可解释、可复现的基线模型，输出 ETF 横截面预测分数和候选池。
- DoubleEnsemble 作为稳健预测模型，通过样本重加权与模型集成降低标签噪声和过拟合风险。
- DoubleEnsemble 属于预测层，不替代仓位、回撤、流动性和熔断风控。
- 所有模型必须记录数据版本、特征版本、标签定义、随机种子、训练窗口、超参数和模型文件摘要。
- 必须执行时间序列滚动验证、样本外测试、交易成本敏感性、特征漂移和模型稳定性检查。

#### 9.2 精研验真层：TradingAgents 风格的证据型多 Agent

- 对初筛候选资产并行执行基本面、技术面、新闻、公告、风险和反方审查。
- Agent 只允许调用白名单只读工具，不得下单、修改仓位或改变风控参数。
- 每项结论必须关联数据集、时间、字段、公告或新闻来源；缺乏证据时标记“原因未验证”。
- 输出结构化的 `通过 / 观察 / 排除` 结论、风险标签、证据清单和冲突意见，不直接生成实盘订单。
- 建立人工核验样本集，对提示词和模型版本变更执行回归测试，监控幻觉率、引用错误率和结论漂移。

#### 9.3 仓位微调层：受约束 PPO

- PPO 仅在基线策略给出的目标仓位附近做小幅调整，第一版限制为基线仓位的 `0.8–1.2` 倍。
- PPO 不决定资产是否进入候选池，不得新增被精研层排除的资产，也不得突破任何确定性风险上限。
- 状态仅使用决策时点可获得的信息；动作、奖励、成本和下一状态严格按时间顺序生成，禁止未来数据。
- 奖励函数必须扣除手续费、滑点、换手惩罚、回撤惩罚和风险暴露惩罚。
- 必须与固定仓位、波动率目标仓位等简单基线比较；若样本外改善不稳定，则自动退回基线仓位。
- 第一阶段只允许离线训练和事件驱动回测；通过后进入纸面仿真，不直接进入实盘。

#### 9.4 最终安全垫：确定性风险引擎

- 最终订单仍必须经过现有风险引擎，执行优先级高于 LightGBM、DoubleEnsemble、TradingAgents 和 PPO。
- 强制检查单资产上限、组合暴露、相关性、波动率目标、流动性、换手率、单日亏损、最大回撤、连续亏损、数据陈旧、API异常和全局熔断。
- 任一模型不可修改风险阈值；阈值变更必须版本登记、人工确认并写入审计日志。
- 模型失效、数据缺失、Agent证据不足或 PPO 输出异常时，系统降级到零新增仓位或预先批准的基线策略。

#### 9.5 数据流与决策边界

`数据与特征版本 → Qlib/LightGBM/DoubleEnsemble候选池 → TradingAgents证据验真 → 基线目标仓位 → PPO有限微调 → 确定性风险引擎 → 事件回测/纸面仿真`

任何上游模块只能缩小候选范围或提出目标值；只有确定性风险引擎可以批准进入纸面执行管线，真实交易仍由独立人工审核闸门控制。

#### 9.6 分阶段实施顺序

1. 建立 ETF 可交易池、复权行情、停牌/流动性过滤和时间序列标签。
2. 完成 Qlib 数据适配与 LightGBM 基线，生成可复现候选池。
3. 加入 DoubleEnsemble，对比 IC、ICIR、换手、成本后收益和样本外稳定性。
4. 将现有 DeepSeek 证据研究扩展为 TradingAgents 风格的多角色验真，但保持只读。
5. 建立 PPO 仿真环境，先与固定仓位和波动率定仓基线对照。
6. 接入现有确定性风控、事件回测和仿真账户，完成端到端审计日志。
7. 连续纸面仿真至少 30 个真实交易日，通过对账、稳定性和安全审查后，才允许申请人工实盘评估。

#### 9.7 验收标准

- 初筛模型必须有严格的训练、验证、样本外和滚动检验结果。
- 报告必须包含含成本收益、最大回撤、换手率、容量、市场状态分解和相对简单基线的增量价值。
- TradingAgents 验真结果必须可追溯，不能把模型解释标记为事实证据。
- PPO 必须证明样本外表现相对简单基线具有稳定增量，且在压力测试中不突破仓位边界。
- 任一模块失败时必须安全降级；所有真实交易与 AI 执行开关继续保持关闭。

## 发布闸门

每个阶段必须满足：单元测试通过、数据契约通过、审计日志完整、无未来数据测试通过、真实交易开关为 false、风险限制可解释。未完成样本外测试和仿真交易，不允许进入实盘。
