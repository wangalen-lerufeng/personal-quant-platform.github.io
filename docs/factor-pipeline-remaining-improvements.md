# 因子与模型流水线：剩余完善事项

> 项目：`personal-quant-platform`  
> 范围：Phase 9、Qlib、LightGBM、DoubleEnsemble、因子处理、模型准入和纸面交易  
> 状态：后续整改与验收清单  
> 安全原则：完成这些改造不等于具备实盘条件；真实交易继续保持关闭。

## 1. 当前阶段结论

系统已经完成以下关键改造：

- 因子缺失率报告；
- 截面 MAD 去极值；
- 行业和市值中性化；
- 截面 Z-Score；
- 训练期单因子 Rank IC 诊断；
- 因子相关性去冗余；
- LightGBM 与 DoubleEnsemble 时间切分训练；
- 样本外 Rank IC / ICIR；
- 每日横截面分组收益；
- 换手与成本后净值；
- 市场状态分组；
- 模型准入门；
- 未达标时保持现金、停止生成订单；
- 纸面交易和运行历史持久化。

剩余工作主要集中在统计边界、准入严格度、成本真实性、时点数据和组合风险控制。

## 3. P0：因子筛选必须发生在模型训练之前

### 3.1 当前潜在问题

当前流程描述为：

```text
模型训练
→ 单因子诊断
→ 相关性聚类
```

如果诊断结果没有触发重新训练，那么因子筛选只是事后报告，本轮模型仍然使用未筛选的完整特征。

### 3.2 正确流程

```text
训练期原始因子
→ 缺失检查
→ 去极值、中性化、标准化
→ 训练期 IC 诊断
→ 训练期相关性聚类
→ 验证期确认筛选结果
→ 固定最终因子名单
→ LightGBM / DoubleEnsemble 训练
→ 测试期评价
```

### 3.3 实现要求

- 因子筛选只能读取训练期数据；
- 验证期只能用于确认阈值和调参；
- 测试期不能改变因子列表；
- 最终因子清单必须传入 LightGBM 和 DoubleEnsemble；
- 因子清单改变后必须重新训练模型；
- 运行历史记录原始因子数、剔除数、最终因子数和剔除原因。

### 3.4 验收标准

- 日志明确显示 `raw_features → selected_features → model.fit`；
- 测试期标签变化不会改变最终因子名单；
- 相关性聚类后被剔除的因子不出现在模型输入；
- LightGBM特征重要性只包含最终保留因子。

## 4. P0：时间切分增加标签隔离区

### 4.1 风险说明

如果标签是未来 N 日收益，训练集最后 N 日的标签会使用验证期价格；验证集最后 N 日的标签会使用测试期价格。

即使特征没有未来数据，也可能通过标签跨界形成泄漏。

### 4.2 推荐方式

```text
训练集
→ purge：删除边界前 N 日样本
→ embargo：保留 N 日隔离
→ 验证集
→ purge / embargo
→ 测试集
```

隔离长度至少等于：

```text
最大预测周期 + 最大执行延迟
```

示例：

- 预测未来1日：至少隔离1个交易日；
- 预测未来5日：至少隔离5个交易日；
- 次日成交后持有5日：根据标签定义考虑6日左右边界。

### 4.3 验收标准

- 训练标签使用到的最后一个价格日期不晚于训练边界；
- 验证标签不读取测试期价格；
- 单元测试覆盖1日、5日和20日标签；
- 报告显示每个区间的特征日期和标签覆盖日期。

## 5. P0：加强模型准入门

### 5.1 当前规则不足

如果仅要求：

```text
Rank IC > 0
ICIR ≥ 0
扣费后收益 > 0
```

以下微弱随机结果也可能通过：

```text
Rank IC = 0.001
ICIR = 0.001
扣费后收益 = 0.01%
```

### 5.2 建议准入维度

模型准入至少综合：

- 样本外 Rank IC；
- Rank ICIR；
- Rank IC 为正的日期比例；
- 分组收益单调性；
- Top 组相对基准收益；
- 扣费后净收益；
- 最大回撤；
- 换手率；
- 多个 Walk-forward 窗口的稳定性；
- 数据覆盖率与有效股票数量。

### 5.3 阈值确定原则

- 阈值必须由训练集和验证集确定；
- 测试集只能应用已经锁定的阈值；
- 阈值和版本必须落盘；
- 不允许看到测试结果后降低阈值；
- 不建议把所有阈值永久写死为经验常数。

### 5.4 拒绝后的行为

```text
模型准入：失败
候选池：仅供诊断或清空
TradingAgents：跳过
PPO：跳过
目标仓位：0
现金：100%
订单：0
允许正式仿真：否
允许实盘：否
```

### 5.5 验收标准

- Rank IC为负时订单必为0；
- ICIR未达锁定阈值时订单必为0；
- 扣费后净收益非正时订单必为0；
- 模型拒绝原因结构化记录；
- 网页明确展示准入状态和每条规则结果。

## 6. P0：将分组收益单调性纳入准入

### 6.1 每日横截面分组

必须按照每个交易日分别分组：

```text
当日全部资产预测分数
→ Q1、Q2、Q3、Q4、Q5
→ 计算各组下一期收益
→ 再对时间求均值
```

不能将不同日期混合后统一 `qcut`。

### 6.2 建议输出

- Q1～Q5平均收益；
- Q5-Q1收益；
- Top组相对基准收益；
- 分组编号与收益的Spearman相关性；
- 相邻组方向一致率；
- 每个交易日有效组数；
- 扣除成本后的Top组收益。

### 6.3 准入逻辑

可以定义：

```text
monotonicity_score = Spearman(Q组编号, Q组平均收益)
```

准入时要求：

- 单调性方向与模型定义一致；
- Top组收益高于中间组和Bottom组；
- 扣费后的Top组相对收益为正；
- 多个窗口中单调关系不完全失效。

### 6.4 验收标准

- 分组收益不单调时模型不会仅凭微弱正Rank IC通过；
- 报告显示单调性得分；
- 单元测试覆盖严格单调、完全反向和随机三类样本。

## 7. P1：细化交易成本模型

### 7.1 当前问题

固定使用：

```text
股票 0.30%
ETF 0.15%
```

需要明确这是单边成本、双边成本，还是组合换手成本率。

### 7.2 建议拆分

股票成本：

- 买入佣金；
- 卖出佣金；
- 卖出印花税；
- 过户费；
- 最低佣金；
- 买入滑点；
- 卖出滑点；
- 市场冲击成本。

ETF成本：

- 买卖佣金；
- 最低佣金；
- 滑点；
- 市场冲击；
- 明确是否适用印花税。

### 7.3 成本计算口径

```text
当期成本
= 买入成交额 × 买入成本率
+ 卖出成交额 × 卖出成本率
+ 最低佣金调整
+ 冲击成本
```

组合层面需要显示：

- 毛收益；
- 总佣金；
- 税费；
- 滑点；
- 冲击成本；
- 成本拖累；
- 净收益。

### 7.4 验收标准

- 零换手时成本为0；
- 买入和卖出成本分别计算；
- 股票和ETF使用不同税费配置；
- 成本参数保存到运行历史；
- 网页显示成本明细而非只有总成本率。

## 8. P1：行业数据遵守时点原则

### 8.1 当前风险

`daily_basic`市值是按日数据，适合历史时点计算；但若行业来自最新 `stock_basic.industry`，可能把当前行业分类回填到过去。

### 8.2 改进要求

中性化数据应记录：

```text
industry_source
industry_effective_date
market_cap_date
neutralization_date
```

如果无法获得历史行业分类，报告必须声明：

```text
行业分类使用当前静态分类，可能存在历史分类偏差。
```

### 8.3 验收标准

- 市值值来自对应交易日；
- 行业字段标明来源和有效日期；
- 缺失行业股票有明确处理规则；
- 中性化失败时不静默返回原始因子；
- 中性化前后行业暴露有对比报告。

## 9. P1：ETF替代暴露控制

ETF跳过上市公司行业与市值中性化是合理的，但需要控制ETF之间的重复暴露。

建议加入：

- 宽基、行业、主题、债券、商品等分类；
- 跟踪指数；
- 成分股重叠度；
- 行业暴露；
- 大盘、中盘、小盘风格；
- ETF规模；
- 日均成交额；
- 跟踪误差；
- 同类ETF只保留流动性和费用更优者。

组合约束建议：

```text
同类ETF数量上限
单一指数暴露上限
成分重叠度上限
单只ETF仓位上限
主题ETF总仓位上限
```

## 10. P1：市场状态改为多维标签

### 10.1 当前问题

“上涨趋势、高波动、流动性紧张”可能同时发生。强制放入六个互斥类别可能丢失信息。

### 10.2 推荐结构

```text
趋势维度：上涨 / 下跌 / 震荡
波动维度：高 / 中 / 低
流动性维度：正常 / 紧张
异常维度：正常 / 数据异常 / 极端行情
```

示例：

```text
上涨趋势 + 高波动 + 正常流动性 + 无异常
```

### 10.3 防泄漏要求

- 当日状态只能使用当日及以前数据；
- 滚动分位数阈值不能使用未来期间；
- HMM若启用，必须使用过滤概率而非全样本平滑状态；
- 状态参数只能在训练期拟合。

## 11. P1：增加 Walk-forward 验证

单次70/15/15切分可能偶然适合某一段市场。

建议滚动验证：

```text
窗口1：训练A → 验证B → 测试C
窗口2：训练A+B → 验证C → 测试D
窗口3：训练A+B+C → 验证D → 测试E
```

每个窗口记录：

- 最终因子列表；
- 模型参数；
- Rank IC / ICIR；
- 分组收益；
- 成本后收益；
- 换手率；
- 最大回撤；
- 市场状态表现；
- 准入结论。

模型必须在多个窗口中保持基本稳定，不能只依赖最后一个测试段。

## 12. P2：统计显著性与稳定性

建议补充：

- Rank IC为正比例；
- Rank IC t统计量；
- p值；
- Newey-West或区块Bootstrap置信区间；
- 滚动Rank IC；
- 分年度表现；
- 多随机种子结果；
- 因子重要性稳定性；
- 因子入选频率；
- 多重检验修正。

注意：金融时间序列存在自相关，不能只使用独立同分布假设下的普通显著性检验。

## 13. P2：成交限制和容量

纸面交易和回测需要进一步模拟：

- 停牌；
- 一字涨停无法买入；
- 一字跌停无法卖出；
- 普通涨跌停成交概率；
- T+1；
- 100股整数倍；
- 部分成交；
- 委托延迟；
- 成交额参与率；
- 冲击成本随订单规模变化；
- 可用资金限制；
- 最低佣金；
- 调仓日无法成交后的订单处理。

容量估计不能仅用：

```text
Top组成交额中位数 × 固定参与率
```

还应报告组合中最弱流动性标的、预期成交天数和冲击成本敏感性。

## 14. P2：数据与模型版本指纹

每次运行建议保存：

- 数据源；
- 查询时间；
- 数据起止日期；
- 股票池版本；
- 复权方式；
- 数据文件哈希；
- 因子表达式；
- 因子处理参数；
- 最终因子名单；
- 标签定义；
- 训练、验证、测试边界；
- purge/embargo长度；
- 模型参数；
- 随机种子；
- 成本配置；
- 风控配置；
- 代码版本；
- 运行时间；
- 准入结论及原因。

目标是任何一次历史运行都能重新构建，而不是只保留最终收益数字。

## 15. 推荐最终流程

```text
1. Tushare数据与历史股票池
2. 复权、停牌、涨跌停和流动性处理
3. 生成严格可执行的前向收益标签
4. 时间切分并加入purge/embargo
5. Qlib计算原始因子
6. 缺失检查、MAD去极值、中性化、截面标准化
7. 训练期IC诊断和相关性聚类
8. 验证期确定筛选规则与模型参数
9. 锁定最终因子、参数和准入阈值
10. LightGBM / DoubleEnsemble重新训练
11. 测试期生成一次样本外预测
12. Rank IC、分组收益、成本、回撤和市场状态评价
13. 模型准入门
14. 达标后生成候选池
15. TradingAgents证据验真
16. PPO有限仓位微调
17. 确定性风险控制
18. 事件驱动回测与纸面交易
19. 完整审计记录
20. 满足长期验收条件后才可申请实盘
```

## 16. 建议开发批次

### 批次A：立即处理

- 调整因子筛选与训练顺序；
- 增加purge/embargo；
- 加强模型准入门；
- 将分组单调性纳入准入；

### 批次B：成本与时点数据

### 批次C：稳健性与仿真真实性

- Walk-forward；
- 统计显著性；
- 涨跌停、T+1和部分成交；
- 容量与冲击成本；
- 数据和模型版本指纹。

## 17. 完成定义

只有满足以下条件，才能认为因子—模型研究闭环完成：

- 因子只在训练期筛选；
- 测试期从未参与选因子、调参或改阈值；
- 时间边界完成purge/embargo；
- 模型输出通过样本外多维准入；
- 成本后表现为正且回撤可控；
- 多个Walk-forward窗口表现稳定；
- 不同市场状态下的失效范围已知；
- 订单经过确定性风控；
- 模型拒绝时系统保持100%现金；
- 每次运行均可审计和复现；
- 真实交易仍默认关闭并需要人工确认。

---

回测收益和纸面交易结果不代表未来收益。本平台用于可重复、可验证、风险可控的量化研究和交易辅助，不能承诺盈利。
